# Reference architecture

**Status:** Placeholder for v0.8.

A later reference architecture should describe, in vendor-neutral terms:

- Discovery of capabilities
- Distinction of experience and realization
- Composition and paved paths
- Encoded governance
- Consumption by humans, products, software systems, automation, and agents
- Learning back into the system

It must stay conceptual enough that no product is required to "comply."
Implementation notes belong in
[Reference implementations](../10-reference-implementations/README.md),
and even there no implementation is canonical.
