# Capability characteristics

Capability maturity is **not** automation maturity.

Do **not** use a ladder where human = immature and automation = mature.

A human-realized security architecture capability may be extremely
mature. A brittle scripted path may be immature.

Consider characteristics independently, as a spectrum, not as a score:

- explicitness
- repeatability
- degree of human judgment
- organizational independence
- composability
- governance
- observability

This repository does not define numerical levels, an assessment
framework, or certification.

See also [Organizational independence](organizational-independence.md).
Each dimension is described as a spectrum, with what you would observe at
either end, in
[Maturity characteristics](../06-maturity-model/README.md).
