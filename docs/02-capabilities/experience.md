# Experience

**Experience is the means by which a consumer discovers, understands,
requests, uses, observes, and interacts with a capability.**

Experience is broader than UI.

Experiences may include documentation, human interaction, CLI, API,
portal, pull request, configuration or declaration, IDE, chat, AI agent
interaction, and combinations of these.

A portal that only opens a ticket is still an experience. It has not
made the capability organizationally independent. Experience and
[realization](realization.md) must stay distinct from the
[capability](capability.md) itself.

## Example: AssessNovelSecurityArchitecture

**Capability:** Assess novel security architecture.

**Experience:** Request an assessment, provide context, collaborate with
a security architect, receive findings, discuss exceptions.

**Realization:** A security architect (or a successor), security
standards, threat-modeling practices, organizational knowledge.

The experience can change (a form, a Slack workflow, an agent-mediated
request) without the capability ceasing to exist.
