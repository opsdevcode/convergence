# Brownfield

Do **not** start with reorganizing teams, buying a platform, creating a
graph database, replacing all tooling, or declaring an enterprise
transformation.

**Apply Convergence to a bounded problem.** Do not launch a Convergence
transformation.

A practical starting point, sketched here and aligned with the
[initial application method](../12-method/README.md):

1. Pick one painful, recurring engineering intent or value flow.
2. Trace it end to end.
3. Record tickets, queues, approvals, meetings, Slack messages, emails,
   spreadsheets, manual actions, and tribal-knowledge steps.
4. Identify the expertise behind each interaction.
5. Classify interactions approximately as novel judgment, repeatable
   expertise, governance, execution, or accidental process.
6. Identify candidate capabilities (what the system is already able to
   do, even if only one specialist can do it).
7. Improve capability explicitness and ownership.
8. Encode repeatable knowledge where valuable.
9. Improve the consumer experience.
10. Measure outcomes you can own; trace contributions you cannot.
11. Repeat **only if** another bounded problem warrants it.

Those bullets are **not** a second process and not an implementation
program. They sit under five moves when you use the method:
**Scope** (1), **Trace** (2–4), **Diagnose** (5–6), **Intervene** (7–9),
**Observe** (10–11). Steps 6–9 apply only when diagnose supports them.

Not every handoff is bad. The goal is not maximum self-service.

**The goal is minimum unnecessary coordination.**
