# Patterns

**Status:** Placeholder for v0.7.

Patterns should be extracted from practice, not invented to fill a catalog.
Candidates already implied by earlier documents, to write up later:

- Standard path as a composed capability (`DeployApplication`-style)
- Exception path as an explicit, rare capability with heavier human
  involvement
- Policy-on-edge (who may compose what) vs. policy-in-node
- Feedback encoded as contract tests after incidents

Until then, do not treat this folder as empty of ideas. The rest of the
body of knowledge is the source; this folder is the index.
