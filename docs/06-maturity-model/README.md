# Maturity model

**Status:** Placeholder for v0.6.

A maturity model should help an organization recognize how far delivery
still runs through organizational handoffs versus shared capabilities, and
whether specialties remain intact. It should not certify vendors, rank
companies, or imply that a Convergence team is the goal.

Draft dimensions to develop later:

- Default interface: queue vs. capability contract
- How much reliability, security, and cost live in contracts vs. after the
  fact
- Whether agents and automation consume the same graph as humans
- Whether learning changes capabilities on a known cadence

Do not use numeric scores until the dimensions are argued in the open.
